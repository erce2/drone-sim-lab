# 03 · 任务设计：把"悬停"升级成"穿门竞速"

> 目标：在官方 Quadcopter 任务的骨架上，做一个**前沿感强、但实现量可控**的任务。
> 无人机竞速（Drone Racing / AI Grand Prix）是近年最热的无人机学习型控制基准之一，
> 而它的最小可复现版本，就是把"飞到随机点"换成"依次穿过若干门"。

---

## 1. 为什么选这个任务

| 候选任务 | 实现复杂度 | 前沿度 | 判断 |
|---|---|---|---|
| 悬停/定点（官方自带） | 极低 | 低 | 只够熟悉框架，写不进简历 |
| **门穿越（本次）** | 中 | 高 | 有明确的阶段式目标、可量化成功率，接近真实竞速 |
| 移动平台降落（船载） | 中高 | 高 | 需要更强的扰动建模，留作进阶 |
| 视觉端到端（相机） | 高 | 很高 | 需要渲染管线 + 视觉 encoder，算力与时间成本高 |
| 抓取/接触（机械臂） | 高 | 中 | 偏离无人机方向 |

门穿越的好处：**奖励是天然稀疏的（过门/不过门）**，所以我们既要有成型奖励（距离），又要有事件奖励（过门），
这正好涵盖 RL 奖励设计里最核心的一课。

---

## 2. 任务定义（可直接对照代码）

```
场地: 每个环境一块独立平地, 原点由 env_origins 给出
机体: Crazyflie, 从原点 (0,0,0.5) 起飞
赛道: 3 个门, 中心 x = [2, 4, 6] m, y ~ U(-1,1), z ~ U(0.5,1.5)
      门法向 = +x, 窗口 0.9 m (宽) x 0.7 m (高)
目标: 依次穿过 3 个门
成功: gate_idx 达到 3
失败: 坠地(z<0.1) / 超高(z>2.5) / 横向越界(|y|>3.5) / 漏门(越过门平面 1.5m 仍未进窗口)
时间: 8 s (400 个决策步 @ 50 Hz)
```

坐标系约定（**整个项目最容易出错的地方**）：

- 所有"世界坐标"必须相对各自环境的 `env_origins`；
- 门的相对位置在**机体坐标系**里给网络看，而不是世界坐标；
- 越界判据用**环境局部坐标**（这是本次踩的第一个坑，见第 5 节）。

## 3. 观测设计（13 维）

| 维度 | 内容 | 为什么 |
|---|---|---|
| 0–2 | 机体线速度 | 阻尼控制必需 |
| 3–5 | 机体角速度 | 姿态内环必需 |
| 6–8 | 投影重力（≈姿态） | 无万向锁，和 IMU 同构 |
| 9–11 | 当前门在机体坐标系的位置 | 相对量，网络不需要学绝对地图 |
| 12 | `gate_idx / num_gates` | 阶段信息，让策略知道"我在第几关" |

> 进阶练习：加"下一个门"的相对位置（给前瞻），或者加入短历史的堆叠帧（隐式速度估计）。

## 4. 奖励设计：成型 + 事件

### v1：稠密距离奖励（成功，但最终被策略钻空子）

```
r = 15.0 * (1 - tanh(||p - gate|| / 0.8)) * dt     # 成型项：靠近当前门就给分
    - 0.05 * ||v_body||² * dt
    - 0.01 * ||ω_body||² * dt
    + 2.0  (穿门一次)
    + 5.0  (完赛)
```

结果：**300 轮 / 39.3M 步 / 4 分 54 秒，成功率 59%，平均过门 2.44**。看起来不错。

然后我 `--resume` 继续训练到 1200 轮，出现了教科书式的 **reward hacking**：

| 指标 | 300 轮时 | 续训 80 轮后 |
|---|---|---|
| 平均回报 | 5.3 | **65** |
| 成功率 | 59% | **0%** |
| 策略行为 | 依次穿门 | **在 0 号门前悬停，不穿门** |

原因很直白：`1 - tanh(d/0.8)` 只和"离门多近"有关，**和方向无关**。
停在门前 0.3 m 处，每步都能拿满 `0.3` 奖励，跑满 400 步就是 +120；
而真去穿门，一旦从窗口边缘飞过（判定"漏门"）就立刻终止、一分不多。
**对策略来说，"不飞"严格优于"冒险飞"。**

> 这就是为什么很多论文里 reward shaping 是最大的工程工作量：
> 你写的不是"目标"，你写的是"策略会找到的最省力的作弊路径"。

### v2：势能式进度奖励（本次最终采用）

```
r = 3.0 * (d_{t-1} - d_t)                          # 势能式整形：只有"变近"才给分
    + 5.0   (穿门一次)
    + 10.0  (完赛)
    - 5.0   (坠毁/越界)                              # 抑制"早点结束"
    - 0.05  (每控制步的 alive 代价)                   # 抑制磨蹭
    - 0.05 * ||v_body||² * dt  - 0.01 * ||ω_body||² * dt
```

为什么这样能堵住漏洞：

- **悬停时 `d` 不变 → 进度奖励为 0**，而 alive 惩罚每步 -0.05，磨蹭变成负收益；
- 势函数差分（potential-based shaping）在理论上**不改变最优策略**，是奖励整形里少数有保证的写法；
- 事件奖励 +10/+5 提供稀疏但明确的目标信号。

结果：**106 轮成功率就达到 93.6%，149 轮 99.6%**（比 v1 快 3 倍且更高）。

> 这两次训练日志都保留着，可以作为"reward design 会怎样失败"的直接证据——
> 面试里讲这个，比讲"我调出了 99% 成功率"有说服力得多。

## 5. 三个必须踩过的坑（本次真实踩过）

### 坑 1：世界坐标 vs 环境局部坐标

初始版本直接用 `pos[:, 1].abs() > max_lateral` 判越界。结果 8 个环境**每步全部重置**，因为
`env_origins[0] = (12, -4, 0)`，机体一出生 `|y| = 4 > 3.5`，被判坠毁。

```python
pos_local = pos_w - self._terrain.env_origins   # 必须这样
```

**教训**：Isaac Lab 里凡是"阈值判据"，先问一句"这是相对谁的？"

### 坑 2：`R @ z` 和 `R^T @ z` 写反

手写姿态控制器里需要"期望推力方向在机体系下的表示"，即 `R^T @ z_des_w`：

```python
torch.einsum("nij,nj->ni", R, z)    # 错: 这是 R @ z
torch.einsum("nji,nj->ni", R, z)    # 对: 这是 R^T @ z
```

体轴一转动，错误版本给出的旋转轴方向就完全错，姿态环变成正反馈，飞机 2 秒内翻到 136°。

**教训**：`R` 的约定（body→world 还是 world→body）要写在注释里，不能靠记忆。

### 坑 3：事件检测放在哪个钩子

`DirectRLEnv.step()` 的顺序是：

```
_get_dones  →  _get_rewards  →  _reset_idx  →  _get_observations
```

"穿门"这个事件：

- 必须在 `_get_rewards` 之前算好（奖励要用）；
- 必须在 `_reset_idx` 之前算（否则位置已被重置，`prev_rel_x` 失去意义）。

所以只能放在 `_get_dones` 里（它是唯一同时满足这两条、且每步必被调用的钩子）。
这在官方文档里没有明说，但读一遍 `direct_rl_env.py` 的 `step()` 就清楚了——
**这就是"会用框架"和"理解框架"的分界线**。（参考 [direct_rl_env.py:332](../reference/direct_rl_env.py)）

## 6. 手工控制器（对照组）

`labs/scripted_controller.py` 实现了一个标准级联几何控制器：

```
位置误差 --P--> 期望速度 --P--> 期望加速度 a_des
    ├── 推力 = m * (a_des · b3)              # b3 = 机体 z 轴
    └── 期望姿态 z_des_w = a_des / |a_des|
            └── 姿态误差 delta = e3 × (R^T z_des_w)
                    └── 力矩 τ = I (ω_n² delta − 2ζω_n ω)   # 带宽 12 rad/s
```

两个工程要点：

1. **带宽必须满足 `ω_n·dt << 1`**。50 Hz 控制下用 110 rad/s 的带宽，离散化直接发散；
   一开始用 110 就翻车，降到 12 才稳定。
2. **力矩增益要乘转动惯量**。I 从仿真里读（`root_physx_view.get_inertias()`，实测 1.67e-5 kg·m²），
   不要硬编码——换机型就失效。

对照组的意义：**它证明环境和物理是对的**，同时给 RL 一个"人类水平"的参照。

## 7. 如果要继续往前推（进阶方向，按性价比排序）

1. **域随机化**：`_reset_idx` 里随机化 `thrust_to_weight`、质量、动作延迟（一阶惯性），再评估鲁棒性。
2. **完整赛道几何**：把虚拟门换成 USD 门框（带碰撞），失败方式就多了"撞门框"。
3. **视觉端到端**：加 TiledCamera，obs 换成 RGB，用 CNN 编码——这才是 Isaac Sim 渲染能力的用武之地。
4. **多机竞速**：多个无人机在同一赛道，加避撞奖励。
5. **sim2real**：把动作空间下移到电机层，重建 mixer，用真机数据辨识参数。
